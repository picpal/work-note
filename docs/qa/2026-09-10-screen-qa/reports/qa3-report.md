## FAIL 상세

### [FAIL-1] 링크 대상 노트를 삭제해도 링크가 정상으로 보이고, 클릭하면 보던 노트가 그냥 닫힌다
- 화면/경로: index.html → 에디터 본문(위키링크)
- 재현 절차:
  1) 노트 A(QA3-에디터) 본문에 `[[` 자동완성으로 노트 B(임시-삭제대상) 위키링크를 넣고 ⌘S 저장
  2) 사이드바에서 노트 B 우클릭 → 삭제 → 경고 모달의 "삭제" 확인
     (모달이 "삭제하면 그 링크들은 '연결할 수 없음'이 됩니다"라고 명시함)
  3) 노트 A 화면을 그대로 둔 채 그 링크를 확인하고 클릭
- 기대: 삭제 즉시 링크가 `🔒 연결할 수 없음`(회색·비활성)으로 바뀌고, 클릭해도 아무 일이 없거나 안내가 뜬다.
- 실제: 링크가 파란 정상 링크 그대로 남는다(`.cm-wikilink`, `rgb(47,111,219)`). 클릭하면 편집기가 사라지고
  "열린 노트가 없습니다" 빈 화면이 된다 — 보고 있던 노트 A까지 닫히고 아무 메시지도 없다.
  새로고침 후 같은 노트를 열면 그제서야 `🔒 연결할 수 없음`(`.cm-wikilink.broken`)으로 표시된다.
- 추정 원인: `WikilinkWidget.eq()`가 id·label만 비교해서, 대상이 사라져도 위젯이 재생성되지 않는다(`resolve` 재호출 안 됨).
- 심각도: 중간 (데이터 손실은 없지만 앱이 방금 예고한 동작과 화면이 어긋나고, 작업 중이던 노트가 닫힌다)
- 증적: `shots/qa3/m3-delete-warn.png` / `shots/qa3/fail1-stale-link-empty-state.png` / `shots/qa3/m3-broken-after-reload.png`

## UX/UI 개선 제안

### [UX-1] 툴바 서식 버튼에 해제(토글 오프)가 없어 마커가 중첩된다
- 화면: 에디터 툴바(굵게·기울임·취소선·인용·목록·체크리스트)
- 현재 동작: 같은 버튼을 다시 누르면 서식이 해제되지 않고 마커가 계속 덧붙는다.
  굵게 2회 → `****굵게토글****` / 목록 2회 → `- - 목록테스트` / 체크리스트 3회 → `- [ ] - [ ] - [ ] …`
  (화면에도 `• ☐ - [ ] - [ ]` 그대로 노출)
- 문제: 잘못 누른 서식을 되돌릴 수단이 툴바에 없다. 원문 마크다운을 직접 지워야 하는데, 라이브 프리뷰라
  원문은 커서를 그 줄에 올려야만 보인다. 특히 목록/체크리스트는 깨진 중첩 리스트로 렌더돼 문서가 눈에 띄게 망가진다.
- 제안: (1) 커서/선택 위치에 같은 서식이 이미 있으면 제거하는 토글로 바꾸고, (2) 최소한 줄 단위 서식(인용·목록·체크리스트)은 중복 접두사를 막는다.
- 우선순위: 중간
- 증적: `shots/qa3/ux1-toolbar-stacking.png`

### [UX-2] H5·H6 제목이 서로 구분되지 않고 본문보다 작게 보인다
- 화면: 에디터 본문 라이브 프리뷰
- 현재 동작: H1 27.2px → H4 16.3px까지는 단계가 보이는데 H5와 H6가 둘 다 15.04px·같은 굵기로 완전히 동일하다.
  본문 문단이 16px이라 H5·H6는 본문보다 작다.
- 문제: 5~6단계 목차를 쓰는 문서(스펙·매뉴얼)에서 지금 몇 단계 제목인지 화면만 보고 구분할 수 없고, 제목이 본문보다 작아 계층이 역전돼 보인다.
- 제안: H5는 본문과 같거나 약간 크게(16px), H6는 15px + 색/자간 차이로 최소 두 단계가 구분되게 조정.
- 우선순위: 낮음
- 증적: `shots/qa3/ux2-h5-h6-same-size.png`

### [UX-3] `[[` 자동완성에서 루트 노트만 아이콘 없이 다르게 보인다
- 화면: 에디터 본문 `[[` 자동완성 팝업
- 현재 동작: 폴더 안 노트는 `📄 노트명 … 📁 폴더명`으로 정렬돼 보이는데, 루트 노트(README, QA3-에디터)는 폴더 경로가 없어
  노트 아이콘까지 사라지고 들여쓰기가 어긋난 채 표시된다. (CSS가 `li:has(.cm-completionDetail)` 조건으로 아이콘을 붙인다)
- 문제: 같은 목록에서 항목 두 종류가 다른 서식으로 보여 "이건 노트가 아닌가?" 하고 한 번 더 확인하게 된다.
  루트에 노트를 많이 두는 사용자일수록 목록 절반이 어긋나 보인다.
- 제안: 아이콘 조건을 detail 유무가 아니라 위키링크 항목 여부(옵션 `type`/전용 클래스)로 바꾸고, 경로가 없으면 폴더 칩만 생략한다.
- 우선순위: 낮음
- 증적: `shots/qa3/m1-wikilink-autocomplete.png`

### [UX-4] 아웃라인 패널이 좁은 창에서 예고 없이 사라진다
- 화면: 에디터 우측 아웃라인(TOC)
- 현재 동작: 본문 영역이 1240px 이하가 되면 `.outline { display:none }`으로 통째로 감춰진다.
  사이드바(264px)를 켠 1440×900 노트북에서는 본문이 1176px라 아웃라인이 아예 보이지 않는다.
- 문제: 1440 폭은 흔한 노트북 해상도인데 그 사용자는 아웃라인 기능이 있다는 사실 자체를 모른다. 숨겨진다는 힌트도, 다시 여는 토글도 없다.
- 제안: 좁을 때는 감추는 대신 툴바 토글로 접근하게 하거나 오버레이/드로어로 띄운다.
- 우선순위: 중간
- 증적: `shots/qa3/m5-outline.png` (1600px에서는 정상 노출)

### [UX-5] 이미지를 문장 한가운데 떨어뜨리면 문단이 그 자리에서 쪼개진다
- 화면: 에디터 본문 드래그앤드롭 이미지 첨부
- 현재 동작: 드롭 좌표의 문자 위치에 `![...](...)\n`을 그대로 끼워 넣는다. `세 번째 줄` 한가운데 놓으면
  원문이 `세 번째 ![img](...)` + `줄`로 갈라져 문장이 이미지 위아래로 찢어진 채 렌더된다.
- 문제: 사용자는 "이 문단 근처에 넣겠다"는 의도로 놓지, 몇 번째 글자 사이에 넣겠다고 조준하지 않는다. 드롭할 때마다 문장을 수동으로 다시 붙여야 한다.
- 제안: 드롭 위치를 문자 단위가 아니라 가장 가까운 줄(블록) 경계로 스냅하고, 이미지 앞뒤로 개행을 함께 넣는다.
- 우선순위: 중간
- 증적: `shots/qa3/n1-drop-inline-image.png`

### [UX-6] 본문에서 쓰고 있는 첨부를 삭제할 때 아무 경고가 없다
- 화면: 에디터 첨부함(AttachmentBar) `×`
- 현재 동작: 본문에 `![...](...)`로 삽입돼 있는 이미지 첨부를 지워도 확인창은 `'파일명' 첨부를 삭제할까요? 되돌릴 수 없습니다.`뿐이고,
  본문에서 몇 군데 쓰이는지는 알려주지 않는다. 삭제 직후 화면에는 (브라우저 캐시 때문에) 이미지가 멀쩡히 보이다가,
  새로고침하면 깨진 이미지 아이콘으로 바뀐다.
- 문제: 노트를 지울 때는 "1개 문서가 이 노트를 참조하고 있습니다"라고 친절히 경고하면서, 첨부는 같은 상황에서 침묵한다.
  사용자는 안 쓰는 파일인 줄 알고 지우고, 문서가 깨진 사실은 한참 뒤에야 발견한다.
- 제안: 삭제 확인 시 본문 참조 개수를 함께 보여주고(노트 삭제 경고와 동일한 톤), 삭제 후 본문의 깨진 이미지 자리에 `첨부가 삭제되었습니다` 플레이스홀더를 렌더한다.
- 우선순위: 중간
- 증적: `shots/qa3/ux6-deleted-attachment-broken-image.png`

### [UX-7] 첨부 삭제만 네이티브 확인창을 쓴다
- 화면: 에디터 첨부함(AttachmentBar) `×`
- 현재 동작: 노트 삭제·이동 경고는 앱 스타일 모달인데, 첨부 삭제만 브라우저 `window.confirm`이다(`AttachmentBar.tsx:42`).
- 문제: 서식·다크모드가 적용되지 않아 튀고, 네이티브 창은 브라우저 창 상단에 뜨는 등 위치가 달라 한 박자 더 걸린다.
  (QA 자동화 중에도 렌더러가 통째로 멈춰 조작이 막혔다 — 실사용에서도 창 전환·포커스 문제가 생길 수 있다)
- 제안: 다른 파괴적 동작과 같은 인앱 확인 모달로 통일한다.
- 우선순위: 낮음

### [UX-8] 토스트가 1.5초 만에 사라져 안내를 읽기 전에 없어진다
- 화면: 전역 토스트(`TOAST_MS = 1500`, App.tsx:152)
- 현재 동작: 성공 알림뿐 아니라 조치가 필요한 안내도 모두 1.5초 뒤 사라진다.
  `프로필에서 Redmine 키를 먼저 등록하세요`, `허용하지 않는 파일 형식입니다: .exe`, `파일이 너무 큽니다 (최대 25MB)` 등.
- 문제: 한국어 한 문장을 읽기에 1.5초는 짧고, 사라진 메시지를 다시 볼 방법이 없다. 무엇이 잘못됐는지 모른 채 같은 조작을 반복하게 된다.
  특히 Redmine 패널은 **검색을 눌러야만** 안내가 뜨고 그마저 1.5초 만에 사라져서, 패널을 처음 연 사용자는 왜 결과가 비었는지 알 수 없다.
- 제안: (1) 에러/안내 토스트는 4~5초로 늘리거나 닫기 버튼을 붙이고, (2) Redmine 패널은 키 미등록 상태를 열자마자 본문에
  `프로필 > Redmine 연동에서 API 키를 등록하세요` 안내로 표시한다(빈 상태 문구를 `검색 결과가 없습니다` 대신 사용).
- 우선순위: 중간
- 증적: `shots/qa3/o3-redmine-panel.png`

## 참고 사항 (판정 외)

- **테스트용 변경**: O3 확인을 위해 관리자 > Redmine 연동을 **켜짐 / `http://redmine.intra`** 로 저장했다. QA3 전용 DB이므로 그대로 두었다.
- **PII 오탐 관찰**: 저장 확인용으로 넣은 13자리 타임스탬프(`O1-수동저장-1789015782259`)가 **주민등록번호로 탐지**됐다.
  하이픈 없는 13자리 숫자를 곧바로 RRN으로 보는 규칙이라, 실제 업무 문서의 주문번호·트랜잭션 ID에서도 오탐이 날 수 있다(별도 확인 권장).
- **QA 도구 관련**: 첨부 삭제의 네이티브 `window.confirm`이 렌더러를 막아 CDP 조작이 중단됐다.
  `js()`로 `window.confirm`을 자동 승인으로 대체한 뒤 삭제 동작을 검증했다(대화상자가 실제로 뜬다는 점은 별도 확인 — UX-7).
