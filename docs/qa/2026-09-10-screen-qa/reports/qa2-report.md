- 대상: http://localhost:8342 (QA2 전용 서버/DB)

## FAIL 상세

### [FAIL-1] 태그를 붙일 수는 있는데 태그로 찾을 수단이 없다
- 화면/경로: index — 에디터 태그 입력줄 / ⌘K 검색 오버레이
- 재현 절차:
  1) 아무 노트나 열고 태그 입력줄에 `qa2tag` 입력 후 Enter → `#qa2tag` 칩 생성, 서버에도 저장됨
  2) ⌘K → `qa2tag` 검색
  3) 결과: `"qa2tag" 와 일치하는 노트가 없습니다` (0개 결과)
  4) 에디터의 `#qa2tag` 칩을 클릭해도 아무 일도 일어나지 않음(× 버튼만 삭제 동작)
- 기대: 태그로 노트를 찾을 수 있어야 함(검색 대상 포함 또는 태그 클릭 시 필터)
- 실제: 검색은 제목+본문만 대상(`SearchModal.tsx` 주석·플레이스홀더 "제목 또는 내용 검색…"에도 명시). 태그 칩은 클릭 핸들러 없음. 즉 **태그는 입력·저장·표시만 되고 소비 경로가 0개**
- 심각도: 중간 (기능은 있으나 목적을 달성 못 함. 사용자가 태그를 붙이는 노력이 전부 버려짐)
- 증적: `shots/qa2/G2-search-results.png`

### [FAIL-2] 폴더에 한번 넣은 노트·폴더를 최상위로 되돌릴 방법이 UI에 없다
- 화면/경로: index — 컨텍스트 메뉴 `이동` 모달 / 사이드바 트리 DnD
- 재현 절차:
  1) 최상위에 노트 생성(빈 트리 영역 우클릭 → 새 노트) — 최상위는 정상적인 위치다
  2) 그 노트를 아무 폴더로 이동(모달 또는 DnD)
  3) 다시 우클릭 → `이동` → 목적지 목록 확인 → **폴더만 나열되고 "루트(최상위)" 항목이 없음**
  4) 트리의 빈 영역(폴더 행 바깥)으로 드래그해도 드롭 타깃 하이라이트가 뜨지 않고 드롭이 무시됨
- 기대: 이동 모달에 "루트(최상위)" 목적지가 있거나, 트리 빈 영역이 루트 드롭 존으로 동작
- 실제: `MoveModal`의 목적지 목록은 폴더만 생성하고, `Sidebar`의 `.tree` 컨테이너에는 `onContextMenu`만 붙어 있어 드롭 핸들러가 없다(`dragOverId` 주석의 `"__ROOT__"`는 구현되지 않은 잔재). 모달 헤더는 현재 부모를 "루트 (최상위)"라고 표시해 루트가 1급 위치임을 인정하면서도 그리로 돌아갈 길이 없다
- 심각도: 중간 (데이터 손실은 없지만 오조작을 사용자가 스스로 되돌릴 수 없음 — 관리자가 DB를 만지거나 노트를 새로 만들어 본문을 옮겨야 함)
- 증적: `shots/qa2/H1-move-modal.png`, `shots/qa2/F9-drop-root.png`

### [FAIL-3] 백엔드가 죽어도 앱은 "저장됨"이라고 말한다 — 그동안 만든 노트는 새로고침하면 사라진다
- 화면/경로: index (HTTP 모드, 앱이 이미 열려 있는 상태)
- 재현 절차:
  1) 로그인해서 index 진입 (정상 동작 확인)
  2) 백엔드 프로세스 종료 (`kill <pid>`, 포트 8342)
  3) 사이드바 빈 영역 우클릭 → `새 노트` (2회)
  4) 트리에 "제목 없는 노트"가 정상적으로 추가되고, 우하단 저장 표시는 `저장됨`
  5) 백엔드 재기동 후 새로고침 → 방금 만든 노트 2개가 **모두 사라짐**
- 기대: 서버 저장에 실패했으면 그 사실이 지속적으로 드러나야 한다(저장 표시가 실패/오프라인 상태, 또는 ConnectionLost 차단 화면). 최소한 재연결 시 재전송되어야 한다
- 실제: 실패 알림은 **1.5초짜리 토스트 `서버 동기화 실패: Failed to fetch` 단 한 번**이 전부다. 그 뒤 저장 표시는 계속 `저장됨`(디바운스 PATCH 큐가 비어 있다는 뜻이라 create 실패를 반영하지 않음). `useVaultSync` 주석대로 create/move는 pending 미러 대상이 아니라 재전송도 없다. ConnectionLost는 **초기 로드 실패에만** 걸리는 가드라 이 경로를 못 잡는다
  - 덧붙여, 프런트가 백엔드와 같은 jar에서 서빙되므로 실제 서버 종료 상태에서 새로고침하면 ConnectionLost가 아니라 브라우저의 `ERR_CONNECTION_REFUSED` 화면이 뜬다. ConnectionLost가 실제로 쓰이는 구간은 "서버는 살아 있는데 API만 실패"(5xx·DB 잠금 등)로 좁다
- 심각도: 높음 (사용자가 유실을 인지할 수 없는 조용한 데이터 손실. 폐쇄망 사내 서버는 재기동·점검이 잦아 마주칠 확률이 낮지 않다)
- 증적: `shots/qa2/I7-sync-fail-toast.png`, `shots/qa2/I7-connection-lost.png`

## UX/UI 개선 제안

### [UX-1] "새 노트 / 새 폴더"가 우클릭 안에만 있다
- 화면: index 사이드바
- 현재 동작: 노트·폴더 생성은 트리 빈 영역 또는 폴더 행을 **우클릭**해야만 나온다. 사이드바 상단 버튼은 검색·정렬·모두 접기 3개뿐이고 `+` 류 버튼이 없다
- 문제: 노트 앱에서 가장 빈번한 동작인데 진입점이 화면에 보이지 않는다. 온보딩 노트에 적혀 있긴 하지만, 그 노트를 읽지 않은 사용자(특히 우클릭 습관이 적은 사용자)는 첫 노트를 만드는 방법을 못 찾는다. 트랙패드 사용자에겐 우클릭 자체가 한 단계 더 어렵다
- 제안: 사이드바 툴바에 `+`(새 노트) 버튼 1개 추가(길게 누르거나 드롭다운으로 새 폴더). 최소한 빈 트리 상태에서는 "첫 노트 만들기" 버튼을 보여줄 것
- 우선순위: 중간

### [UX-2] 휴지통에 "언제 삭제됐는지 / 며칠 남았는지"가 없다
- 화면: 휴지통 모달
- 현재 동작: 헤더에 "삭제한 노트·폴더 (30일 후 자동 영구 삭제)"라고만 쓰여 있고, 각 항목에는 이름과 "노트/폴더" 종류만 표시된다
- 문제: 30일 정책은 알겠는데 **이 항목이 며칠 남았는지**를 알 수 없다. 휴지통을 오래 방치하다 중요한 노트가 소리 없이 사라질 수 있고, 사용자는 그걸 미리 알 방법이 없다
- 제안: 각 행에 삭제 일시와 `n일 남음` 배지 표시, 남은 기간이 짧은 항목(예: 3일 이하)은 강조. 정렬도 임박순 기본
- 우선순위: 중간

### [UX-3] 개인 템플릿 삭제만 브라우저 네이티브 confirm을 쓴다
- 화면: 템플릿 모달 → 내 템플릿 → 삭제
- 현재 동작: `window.confirm("'<이름>' 템플릿을 삭제할까요?")` 네이티브 대화상자가 뜬다
- 문제: 앱의 다른 파괴적 동작은 전부 앱 내부 UI로 확인한다(휴지통 영구삭제=인라인 2단계, 노트 삭제=LinkWarnDialog, 이동=MoveWarnDialog). 여기만 브라우저 기본 팝업이라 모노톤 디자인·다크 모드와 이질적이고, 대화상자 위치·문구 스타일을 제어할 수 없다. (부수적으로 자동화/QA 세션을 완전히 블록시킨다)
- 제안: 휴지통의 `영구 삭제 → 영구 삭제 확인 / 취소` 인라인 패턴이나 `pf-overlay` 확인 카드로 통일
- 우선순위: 낮음

### [UX-4] 토스트가 1.5초 만에 사라지고, 실패 알림도 같은 규칙을 따른다
- 화면: index 전역 (`TOAST_MS = 1500`)
- 현재 동작: 성공·실패 구분 없이 모든 토스트가 1.5초 후 사라진다. 이력이나 다시 보기 수단은 없다
- 문제: "이동할 수 없습니다", "복사에 실패했습니다" 같은 **실패 통지가 유일한 채널인데** 1.5초는 시선이 다른 곳(트리·본문)에 있으면 놓치기 충분하다. 놓치면 사용자는 동작이 성공한 줄 알고 넘어간다. 삭제 토스트에도 "실행 취소"가 없어, 되돌리려면 휴지통이라는 별도 화면을 알고 있어야 한다
- 제안: ① 실패/경고 토스트는 4~5초 + 수동 닫기 버튼 ② 삭제 토스트에 "실행 취소" 액션 추가(휴지통을 몰라도 즉시 복구)
- 우선순위: 중간

### [UX-5] 새로고침하면 트리의 펼침 상태와 정렬이 초기화된다
- 화면: index 사이드바
- 현재 동작: 다크모드·사이드바 너비·밀도·글자 크기는 `wn.settings.v1`로 잘 저장되는데, **폴더 펼침 상태와 정렬 기준은 저장되지 않는다**. 새로고침하면 정렬은 `이름 오름차순`으로 돌아가고, 펼침은 현재 열린 노트의 조상 경로만 자동으로 펼쳐진다
- 문제: 깊은 트리(3~4단)에서 여러 폴더를 펼쳐 놓고 작업하다 새로고침 한 번이면 전부 접힌다. 정렬을 `생성일 내림차순`으로 쓰는 사용자는 매번 다시 지정해야 한다. 다른 표시 설정은 전부 유지되기 때문에 일관성도 어긋난다
- 제안: 펼침 폴더 id 집합과 정렬 키를 `wn.settings.v1`(또는 별도 키)에 같이 저장
- 우선순위: 낮음

### [UX-6] 링크 경고가 "몇 개"만 알려주고 "어디서" 참조하는지는 안 알려준다
- 화면: 노트 삭제 → LinkWarnDialog
- 현재 동작: "1개 문서가 이 노트를 참조하고 있습니다…"처럼 개수만 표시한다
- 문제: 사용자가 삭제 여부를 판단하려면 **어떤 노트가 이걸 참조하는지**를 알아야 한다. 지금은 취소하고 백링크 패널을 따로 찾아 확인한 뒤 다시 삭제해야 한다
- 제안: 경고 카드에 참조 노트 제목 목록(최대 5개 + "외 n개")을 표시하고, 클릭하면 해당 노트로 이동
- 우선순위: 낮음
