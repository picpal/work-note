## FAIL 상세

### [FAIL-1] 권한이 없는 사용자에게 서버가 빈 트리를 주는데 프런트가 시드 vault를 대신 렌더한다
- 화면/경로: 관리자 `권한 관리(#permissions)` → 사용자 화면 `index.html`
- 재현 절차:
  1. 관리자로 `#permissions`에서 폴더 `아키텍처`에 사용자 `S2026-9001` **거부(deny)** ACL 저장
  2. 로그아웃 → `S2026-9001`(방문자)로 로그인
  3. 좌측 트리와 본문을 확인. 브라우저 콘솔에서 `fetch('/api/tree')` 응답도 확인
- 기대: 읽을 수 있는 노트가 없으므로 빈 트리 + 빈 상태 안내
- 실제: `GET /api/tree` → `[]`(백엔드 ACL enforce는 **정상**)인데 화면에는 시드 vault 전체(시작하기·아키텍처·결제 파이프라인·승인 연동 시퀀스·운영 가이드·회의록·README)가 그대로 뜨고, 본문 열람·편집("저장됨")까지 된다.
  근거: `HttpVaultRepository.load()`가 `tree.length ? tree : null`을 반환 → `useVault`가 `saved==null`이면 `SEED` 트리를 유지. 실제로 방문자 화면의 README 수정일은 시드 고정값(2026-06-06)으로, 관리자 화면의 DB 값(2026-09-10)과 다르다.
- 영향: ① 사용자가 실재하지 않는 문서를 진짜 사내 문서로 오인 ② 관리자가 권한 회수를 해도 대상 화면에는 그대로 보여 **권한 설정이 먹혔는지 검증할 수단이 없다** ③ `bootstrapIfEmpty`가 시드를 서버로 업로드하려 시도(방문자는 `res.create` 없어 실패하지만, `일반사용자` 역할이면 남의 vault에 시드가 생성될 수 있음)
- 심각도: **높음**
- 증적: `shots/qa4/FAIL-visitor-sees-seed.png`

### [FAIL-2] 업로드 허용 확장자에 잘못된 문자열이 검증 없이 저장된다
- 화면/경로: `업로드 정책(#uploads)`
- 재현 절차: 1) 확장자 입력란에 `.BAD!` 입력 후 Enter 2) 칩이 `.bad!`로 추가됨 3) 저장 4) `GET /api/admin/settings/upload` 확인
- 기대: 화면 안내("점(.) 없이 소문자로 입력합니다")대로 형식 위반 값은 거부되고 사유를 알려준다
- 실제: 프런트·백엔드 모두 문자 검증이 없어 `allowedExt`에 `"bad!"`가 그대로 저장된다. 이 항목은 어떤 파일과도 매칭되지 않으므로, 관리자는 허용했다고 믿지만 해당 형식 업로드는 계속 거부된다(조용한 오설정).
- 심각도: **낮음** (보안 완화가 아니라 오설정·혼란)
- 증적: `shots/qa4/s1-invalid-ext-accepted.png`

### [FAIL-3] 감사 로그의 행위 일부가 한글 라벨·필터 목록에 없어 원시 코드로 표시된다

## UX/UI 개선 제안

### [UX-1] 사이드바를 접으면 아이콘 레일 없이 통째로 사라지고, 툴팁은 항상 "접기"다
- 화면: 관리자 전 화면(좌측 nav)
- 현재 동작: 접기 버튼을 누르면 13개 항목이 폭 0으로 완전히 사라지고 헤더에 토글 버튼만 남는다. 상태는 `wn.adminNavCollapsed`로 유지되어 새로고침 후에도 접힌 채다. 접힌 상태에서도 버튼 `title`은 "사이드바 접기".
- 문제: 접은 상태에서 다른 화면으로 이동하려면 매번 펼쳤다 접어야 한다. 툴팁이 상태를 반영하지 않아 지금이 접힌 건지 펼친 건지 툴팁만으로는 알 수 없다.
- 제안: 접힘 상태를 아이콘 레일(폭 ~56px, 아이콘만 + hover 툴팁)로 바꿔 이동 경로를 유지한다. 최소한 `title`을 상태에 따라 "사이드바 펼치기/접기"로 토글한다.
- 우선순위: 중간

### [UX-2] 사용자 목록에 이름 컬럼이 없고 정렬도 고정이다
- 화면: `사용자 관리(#users)`
- 현재 동작: 컬럼이 사번·이메일·역할·상태·2FA·마지막 로그인·작업뿐이다. 이름은 행을 클릭해 상세 모달을 열어야 보인다. 검색창은 "사번·이름·이메일 검색"이라 이름으로 찾을 수는 있고, 정렬은 사번 오름차순 고정(헤더 클릭 불가)이다.
- 문제: 이름으로 검색은 되는데 결과에 이름이 안 보인다. `S2026-9001`이 누구인지 확인하려면 행마다 모달을 열어야 하고, 3~4팀 수십 명 규모에서 "최근 로그인이 오래된 계정"이나 "비활성 계정"을 훑는 정렬 수단이 없다.
- 제안: 사번 셀 아래 이름을 보조 텍스트로 넣거나 이름 컬럼을 추가한다(좁은 폭에서는 `col-lastlogin`처럼 숨김 처리). 컬럼 헤더 클릭 정렬을 최소한 `마지막 로그인`·`상태`에 붙인다.
- 우선순위: 중간

### [UX-3] 사용자 이름·이메일을 수정할 방법이 없다
- 화면: `사용자 관리(#users)` 상세 모달
- 현재 동작: 상세 모달의 조작은 "역할 변경 / 비밀번호 초기화 / 2FA 초기화"뿐이다. 백엔드 `PATCH /admin/users/{id}`는 `name`·`email` 수정을 지원하지만 이를 호출하는 UI가 없다.
- 문제: 가입 신청이나 관리자 생성 시 이름·이메일에 오타가 나면 관리자가 고칠 수 없다. 이메일은 2FA 복구 경로라, 잘못 등록되면 해당 사용자는 2FA 분실 시 복구가 막힌다(본인이 프로필에서 고치기 전까지).
- 제안: 상세 모달에 "정보 수정"을 추가해 이름·이메일을 편집하게 한다(백엔드는 이미 지원).
- 우선순위: 중간

### [UX-4] 조상에 deny가 있는 노드에 allow를 저장해도 무효라는 경고가 없다
- 화면: `권한 관리(#permissions)`
- 현재 동작: 부모 폴더에 `S2026-9001 거부`가 있는 상태에서 자식 노트에 같은 주체의 `편집`을 추가·저장하면 "결제 파이프라인 ACL을 저장했습니다" 토스트가 뜨고 그대로 저장된다. 화면에는 deny-sticky 안내 문구가 상시 고정 문구로만 적혀 있다.
- 문제: 관리자는 권한을 부여했다고 믿지만 실제로는 조상 deny가 이겨 아무 효과가 없다. 저장은 성공 메시지까지 뜨므로 잘못됐다는 신호가 전혀 없다.
- 제안: 저장 시(또는 행 추가 시점에) 상속 패널의 같은 주체 deny와 충돌하면 해당 행에 "조상 deny로 무효" 배지를 붙이고, 저장 버튼 옆에 경고를 노출한다. 저장 자체는 막지 않되 결과를 알려준다.
- 우선순위: 높음

### [UX-5] 사용 중인 역할 삭제 실패 메시지가 "누가 쓰는지"를 알려주지 않는다
- 화면: `역할 관리(#roles)`
- 현재 동작: 사용 중 역할 삭제 시 "해당 역할을 사용하는 사용자가 있습니다: qa-reviewer" — 뒤에 붙는 값은 방금 누른 **역할 ID**다. 카드에 "1명"은 표시된다.
- 문제: 관리자가 이미 아는 정보(역할 이름)만 되풀이하고, 정작 필요한 "어떤 사용자를 옮겨야 하는지"는 없다. 사용자 관리 화면에서 역할 필터로 직접 찾아야 한다.
- 제안: 메시지에 사용자 수와 사번 몇 개를 포함하거나(예: "3명이 사용 중: S2026-9001 외 2명"), 역할 카드의 "N명"을 클릭하면 `#users`로 해당 역할 필터가 적용된 채 이동하게 한다.
- 우선순위: 낮음

### [UX-6] 스페이스를 해제해도 자동 부여됐던 팀 edit 권한이 남는데 안내가 없다
- 화면: `팀·스페이스(#teams)`
- 현재 동작: 폴더를 팀 스페이스로 지정하면 해당 팀에 `edit` ACL이 자동 생성된다. 해제 모달은 "폴더와 노트는 그대로 유지됩니다"만 안내하고, 해제 후에도 그 `팀 / edit` ACL은 권한 관리 화면에 그대로 남는다. (참고: 팀 자체를 삭제하면 ACL도 함께 정리된다.)
- 문제: 관리자는 "소유를 해제했으니 접근도 정리됐다"고 믿기 쉬운데, 팀원들은 여전히 그 폴더 전체를 편집할 수 있다. 백엔드는 소유 팀 **교체** 시에는 "이전 팀 grant 잔존" 경고를 반환하면서 해제 경로에만 그 안내가 없어 일관성도 어긋난다.
- 제안: 해제 모달에 "이 팀에 자동 부여된 편집 권한은 유지됩니다 — 함께 회수하려면 권한 관리에서 삭제하세요"를 넣고, 가능하면 "권한도 함께 회수" 체크박스를 제공한다.
- 우선순위: 중간

### [UX-7] 개인정보 점검 화면에 검색·필터가 없다
- 화면: `개인정보 점검(#pii)`
- 현재 동작: 예외 요청 대기 / 전체 개인정보 노트 / 예외 처리된 노트 세 섹션에 전량이 나열된다. 검색창도, 탐지 유형·최종 수정자·기간 필터도 없다.
- 문제: 탐지 노트가 수십~수백 건이 되면 "주민등록번호가 걸린 노트만" 또는 "이번 주에 탐지된 것만" 추려낼 수 없어, 정기 점검이 스크롤 훑기가 된다. 사용자 관리 화면에는 같은 성격의 필터가 이미 있어 화면 간 일관성도 떨어진다.
- 제안: 사용자 관리와 동일한 툴바(검색 + 탐지 유형 셀렉트 + 기간)를 붙이고 건수를 표시한다.
- 우선순위: 중간

### [UX-8] 첨부 최대 용량에 상한이 없고, 하한 보정 사실을 알리지 않는다
- 화면: `업로드 정책(#uploads)`
- 현재 동작: `99999`(≈97GB)를 저장하면 그대로 반영된다. `0`이나 `-5`를 저장하면 서버가 1MB로 보정하고 입력 필드도 `1`로 바뀌지만, 토스트는 똑같이 "저장했습니다"다.
- 문제: 25를 2500으로 잘못 친 오타가 그대로 통과해 폐쇄망 파일 서버 디스크가 노출된다(첨부는 디스크 저장). 반대로 0을 넣은 관리자는 "업로드 전면 차단"을 의도했는데 조용히 1MB 허용으로 바뀐 것을 눈치채기 어렵다.
- 제안: 입력에 `min`/`max`(예: 1~200MB)를 걸고 초과 시 사유를 토스트로 알린다. 보정이 일어나면 "0은 허용되지 않아 1MB로 설정했습니다"처럼 보정 사실을 명시한다.
- 우선순위: 중간

### [UX-9] Redmine 연결 테스트가 없어 주소가 맞는지 확인할 방법이 없다
- 화면: `Redmine 연동(#redmine)`
- 현재 동작: 활성화 토글과 서버 주소만 저장한다. URL 형식 검증("올바른 URL이 아닙니다")은 있지만 실제 도달 여부는 확인하지 않으며, 연결 테스트 버튼도 대응 API도 없다.
- 문제: 형식만 맞고 실제로는 틀린 주소(포트 누락, 오래된 호스트명)를 저장해도 관리자 화면에서는 정상으로 보인다. 실패는 각 사용자가 프로필에서 API 키를 등록하는 시점에야 드러나고, 사용자는 자기 키가 틀린 건지 서버 주소가 틀린 건지 구분할 수 없다.
- 제안: "연결 테스트" 버튼과 서버측 도달성 확인 엔드포인트를 추가해 저장 전에 응답 코드·버전을 보여준다.
- 우선순위: 중간

### [UX-10] 템플릿 삭제만 네이티브 `window.confirm()`을 쓴다
- 화면: `템플릿(#templates)`
- 현재 동작: 삭제 시 브라우저 기본 대화상자가 뜬다(`Templates.tsx:53`). 관리자 화면의 다른 파괴적 작업 — 사용자 비활성화, 역할 삭제, 팀 삭제, 가입 반려, 스페이스 해제 — 은 전부 앱 자체 모달을 쓴다.
- 문제: 생김새·위치·다크모드가 다른 대화상자가 한 화면에서만 튀어나와 흐름이 끊긴다. 앱 모달이 제공하는 맥락(위험 강조 색상, 아이콘, 부가 설명)도 실을 수 없다.
- 제안: 다른 화면과 동일한 확인 모달(`Modal` + `confirmDanger`)로 교체한다.
- 우선순위: 낮음

### [UX-11] 템플릿 편집 패널의 저장 버튼이 화면 밖에 있고 자동 스크롤도 없다
- 화면: `템플릿(#templates)`
- 현재 동작: 편집·추가를 누르면 목록 **아래**에 편집 패널이 펼쳐진다. 1440×900에서 저장/취소 버튼의 y좌표는 957로 뷰포트(900) 밖이며, 패널이 열려도 그쪽으로 스크롤되지 않는다.
- 문제: 이름·본문을 입력한 뒤 저장 버튼이 보이지 않아 "저장이 안 된다"고 오인하기 쉽다(QA 중 실제로 그렇게 오판했다). 템플릿이 늘어날수록 목록이 길어져 편집 패널은 점점 더 아래로 밀린다.
- 제안: 편집 패널을 열 때 해당 패널로 스크롤하거나, 저장/취소를 패널 헤더에 두거나 하단 고정(sticky)으로 만든다.
- 우선순위: 중간

### [UX-12] 1024px 미만에서 화면 전체가 가로로 밀려 좌측 nav까지 사라진다
- 화면: 관리자 전 화면
- 현재 동작: 셸이 `min-width: 1040px`라 그 이하 폭에서는 테이블이 아니라 `#root` 전체가 가로 스크롤된다. 데이터가 잘려서 못 보는 곳은 없지만(13화면 검사, clipped 0건), 오른쪽 끝을 보려고 스크롤하면 좌측 nav가 화면 밖(−642px)으로 나간다.
- 문제: 1024px(노트북 창 분할·태블릿 가로)에서 이미 16px 가로 스크롤이 생긴다. 표의 오른쪽 `작업` 열을 눌러 처리한 뒤 다른 화면으로 가려면 매번 좌측 끝까지 되돌아가야 한다.
- 제안: 좌측 nav를 `position: sticky`로 고정해 가로 스크롤에서 제외하고, 가로 스크롤은 `.table-wrap`(현재 `overflow-x: hidden`) 단위로 옮긴다.
- 우선순위: 낮음 (관리자 화면은 데스크톱 사용이 전제)

### [UX-13] 빈 상태가 화면마다 형식·어투가 다르다
- 화면: 관리자 전 화면
- 현재 동작:
  - 아이콘+제목+설명: 가입 승인 대기 / 팀 / 개인정보 점검(2곳) / 권한 관리(노드 미선택) / 사용자 관리(검색 결과 0)
  - 아이콘+제목만: 공유 링크("활성 공유 링크가 없습니다"), 대시보드 승인 대기 카드("대기 중인 신청 없음")
  - 컴포넌트 없이 회색 인라인 한 줄: 권한 관리 "직접 엔트리가 없습니다 — …" / "상속되는 엔트리가 없습니다." · 스페이스 "지정된 스페이스가 없습니다." · 팀 멤버 "멤버가 없습니다." · 템플릿 "등록된 시스템 템플릿이 없습니다."
- 문제: 같은 "비어 있음"인데 어떤 화면은 안내 카드, 어떤 화면은 눈에 안 띄는 회색 한 줄이라 로딩 실패인지 원래 없는 건지 헷갈린다. 대시보드는 "대기 중인 신청 없음"(명사형), 같은 데이터를 보여주는 가입 승인 화면은 "대기 중인 가입 신청이 없습니다"(문장형)로 표현이 갈리고, 마침표 규칙도 컴포넌트(없음)와 인라인(있음)이 다르다.
- 제안: 문구 규칙을 하나로 정한다 — ① 모든 빈 상태는 `Empty` 컴포넌트 사용 ② 제목은 "~이 없습니다"(마침표 없음) ③ 다음 행동을 알려주는 설명 한 줄 필수 ④ 같은 데이터를 가리키는 화면끼리는 문구 통일.
