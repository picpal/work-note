심각도
D-1

권한이 없는 사용자에게 시드 vault가 자기 노트처럼 보인다

높음

QA4 발견 · 메인 에이전트가 소스로 독립 확인

관리자가 폴더에 deny를 걸어 GET /api/tree가 []를 반환해도, 화면에는 시드 vault 전체(시작하기 · 아키텍처 · 결제 파이프라인 · 운영 가이드 · 회의록 · README)가 뜨고 열람·편집까지 되며 "저장됨"이라고 표시된다.

HttpVaultRepository.load()  →  tree.length ? tree : null   // 빈 트리 = null
useVault                     →  if (saved) dispatch(replace) // null이면 SEED 유지

파급이 보고보다 크다. 같은 wasEmpty 플래그가 bootstrapIfEmpty도 켜므로, 그 사용자는 시드를 서버에 생성하려 시도한다. 방문자 역할은 res.create가 없어 실패하지만 일반사용자 역할이면 실제로 생성된다.

백엔드 ACL enforce는 정상 — 프런트만의 문제다. 그러나 관리자가 권한을 회수해도 대상 화면은 그대로라 권한 설정이 먹혔는지 검증할 수단이 없다. 근거: 방문자 화면 README 수정일이 시드 고정값(2026-06-06)인 반면 관리자 화면 DB 값은 2026-09-10이다.

조치빈 트리와 로드 실패를 구분한다. HTTP 모드에서 []는 "권한 없음 / 빈 vault"라는 유효한 상태이므로 시드로 대체하지 말고 빈 상태를 렌더한다. 시드 부트스트랩은 wasEmpty가 아니라 "서버 최초 기동"이라는 별도 신호에 걸어야 한다.
D-2

백엔드가 죽어도 "저장됨"이라고 말하고, 그동안 만든 노트는 사라진다

높음

QA2 발견

앱이 열려 있는 상태에서 백엔드가 내려가면 앱은 이를 전혀 감지하지 못한다. 노트를 만들면 트리에 추가되고 저장 표시는 저장됨인데 서버에는 아무것도 없다. 새로고침하면 소멸한다.

방어선실제
실패 알림서버 동기화 실패: Failed to fetch 토스트 1.5초 1회가 전부
저장 표시계속 저장됨 — 디바운스 PATCH 큐 기준이라 create 실패를 반영 못 함
재전송useVaultSync에서 create·move는 pending 미러 대상이 아님
ConnectionLost초기 로드 실패에만 걸리는 가드 → 이 경로를 못 잡음

폐쇄망 사내 서버는 재기동·점검이 잦아 마주칠 확률이 낮지 않다. 사용자가 유실을 인지할 수 없는 조용한 데이터 손실이라 심각도가 높다.

조치create·move도 pending write-through에 포함해 재연결 시 재전송하고, 동기화 실패가 누적되면 저장 표시를 실패 상태로 고정한다.
D-3

공유 링크가 미저장 본문을 flush하지 않아 수신자가 빈 노트를 본다

높음

QA1 발견 · 판정은 UX였으나 결과가 결함급이라 승격

본문은 1분 디바운스 PATCH로 저장되는데 공유 링크 생성은 이 flush를 트리거하지 않는다. QA 중 실제로 재현됐다 — 노트 작성 직후 링크를 만들어 열었더니 제목은 제목 없는 노트, 본문은 비어 있고 첨부만 표시됐다. 약 1분 뒤 디바운스가 발화한 뒤에야 정상 렌더됐다.

링크를 만든 사람은 이미 복사해서 전달한 뒤다. 수신자는 빈 노트를 보고 되돌아온다.

조치링크 생성 직전 pending write를 강제 flush(⌘S와 동일 경로)하고, 실패 시 "저장되지 않은 변경이 있습니다" 경고 후 생성 여부를 묻는다.
