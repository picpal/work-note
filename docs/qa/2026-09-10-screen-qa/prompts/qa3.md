## 작업 방식 (반드시 준수)

1. **브라우저는 ego-browser(ego lite)만 사용한다.** Playwright·curl 단독 검증 금지.
   시작 시 `Skill` 툴로 `ego-browser` 스킬을 먼저 호출해 사용법을 읽어라.
   모든 브라우저 조작은 `ego-browser nodejs <<'EOF' ... EOF` 히어독으로 실행한다.
2. **task space 이름은 아래 지정된 것을 쓰고, 라운드마다 재사용**한다.
   `const task = await useOrCreateTaskSpace('<지정된 이름>')`
3. **화면을 실제로 보면서 QA한다.** 각 항목마다 `snapshotText()`로 구조를 확인하고,
   레이아웃·정렬·여백·겹침·잘림이 관련된 항목은 반드시 `captureScreenshot()`으로 눈으로 확인한다.
   DOM만 보고 PASS 판정하지 마라.
4. **코드를 고치지 마라.** 이 작업은 QA다. 소스 수정·git 명령·커밋 전면 금지.
   원인 추정을 위해 소스를 *읽는* 것은 허용된다.
5. 로그인 계정: `admin` / `e2e-admin-pass-1234`
6. 테스트 데이터가 필요하면 화면에서 직접 만들어라(노트·폴더·사용자 등). DB는 너 전용이라 마음껏 써도 된다.

## 리포트

`docs/qa/2026-09-10-screen-qa/reports/qa3-report.md` 에 마크다운으로 **진행하면서 계속 갱신**하라
(한 섹션 끝날 때마다 파일에 append — 끝에 몰아쓰지 마라. 중간에 죽어도 결과가 남아야 한다).

```markdown
## UX/UI 개선 제안
### [UX-1] 제목
- 화면:
- 현재 동작:

- 제안:
- 우선순위: 높음|중간|낮음
```

판정 기준: `PASS`(정상) / `FAIL`(기능 결함·에러·기대와 다름) / `UX`(동작은 하나 개선 필요) / `SKIP`(사유 필수).

**중요**: UX 항목은 "예쁘게 바꾸자" 수준이 아니라 **사용자가 실제로 겪는 불편**을 근거로 써라.
(예: 클릭 타겟이 작아 오조작, 에러 메시지가 원인을 안 알려줌, 되돌리기 수단 없음, 로딩 중 피드백 없음)

전부 끝나면 리포트 첫 줄 상태를 `상태: 완료`로 바꾸고 종료하라. 종료 전 마지막 히어독으로
`await completeTaskSpace(task.id, { keep: false })` 를 호출해 브라우저를 정리하라.
