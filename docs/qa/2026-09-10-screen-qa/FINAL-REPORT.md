## 2. 즉시 조치가 필요한 결함

### 🔴 D-1. 권한이 없는 사용자에게 시드 vault가 자기 노트처럼 보인다
`높음` · QA4 발견 · **메인 에이전트가 소스로 독립 확인**

관리자가 폴더에 deny를 걸어 `GET /api/tree`가 `[]`를 반환해도, 화면에는 시드 vault 전체(시작하기·아키텍처·결제 파이프라인·운영 가이드·회의록·README)가 뜨고 **열람·편집까지 되며 "저장됨"이라고 표시된다.**

```
HttpVaultRepository.load()   →  tree.length ? tree : null   // 빈 트리 = null
useVault                     →  if (saved) dispatch(replace) // null이면 SEED 유지
```

파급이 보고보다 크다. 같은 `wasEmpty` 플래그가 `bootstrapIfEmpty`도 켜므로, 그 사용자는 **시드를 서버에 생성하려 시도**한다. 방문자 역할은 `res.create`가 없어 실패하지만, `일반사용자` 역할이면 실제로 생성된다.

- 백엔드 ACL enforce는 **정상** — 프런트만의 문제다
- 관리자가 권한 회수를 해도 대상 화면은 그대로라 **권한 설정이 먹혔는지 검증할 수단이 없다**
- 근거: 방문자 화면 README 수정일이 시드 고정값(2026-06-06), 관리자 화면 DB 값은 2026-09-10

**조치**: 빈 트리와 로드 실패를 구분한다. HTTP 모드에서 `[]`는 "권한 없음/빈 vault"라는 유효한 상태이므로 시드로 대체하지 말고 빈 상태를 렌더한다. 시드 부트스트랩은 `wasEmpty`가 아니라 "서버가 최초 기동 상태"라는 별도 신호에 걸어야 한다.

### 🔴 D-2. 백엔드가 죽어도 "저장됨"이라고 말하고, 그동안 만든 노트는 사라진다
`높음` · QA2 발견

앱이 열려 있는 상태에서 백엔드가 내려가면 앱은 이를 전혀 감지하지 못한다. 노트를 만들면 트리에 추가되고 저장 표시는 `저장됨`인데 서버에는 아무것도 없다. 새로고침하면 소멸한다.

| 방어선 | 실제 |
|---|---|
| 실패 알림 | `서버 동기화 실패: Failed to fetch` 토스트 **1.5초 1회**가 전부 |
| 저장 표시 | 계속 `저장됨` — 디바운스 PATCH 큐 기준이라 create 실패를 반영 못 함 |
| 재전송 | `useVaultSync`에서 create/move는 pending 미러 대상이 아님 |
| ConnectionLost | **초기 로드 실패에만** 걸리는 가드 → 이 경로를 못 잡음 |

폐쇄망 사내 서버는 재기동·점검이 잦아 마주칠 확률이 낮지 않다. **사용자가 유실을 인지할 수 없는 조용한 데이터 손실**이라 심각도가 높다.

**조치**: create/move도 pending write-through에 포함해 재연결 시 재전송하고, 동기화 실패가 누적되면 저장 표시를 실패 상태로 고정한다.

### 🟠 D-3. 공유 링크가 미저장 본문을 flush하지 않아 수신자가 빈 노트를 본다
`높음` · QA1 발견 (판정은 UX였으나 결과가 결함급)

본문은 1분 디바운스 PATCH로 저장되는데 공유 링크 생성은 이 flush를 트리거하지 않는다. QA 중 실제 재현: 노트 작성 직후 링크를 만들어 열었더니 제목 `제목 없는 노트`, 본문 비어 있음, 첨부만 표시. 약 1분 뒤에야 정상.

링크를 만든 사람은 **이미 복사해서 전달한 뒤**다.

**조치**: 링크 생성 직전 pending write를 강제 flush(⌘S와 동일 경로)하고, 실패 시 "저장되지 않은 변경이 있습니다" 경고 후 생성 여부를 묻는다.

## 3. 나머지 결함

### 🟠 D-4. 감사 로그가 25종 행위를 한글 라벨·필터에서 누락
`중간` · **QA1·QA4가 독립적으로 발견** (교차 검증됨)

화면 스스로 "ISMS · PCI-DSS 추적용"이라 표시하는데, 보안 담당자가 실제로 뽑아야 하는 이벤트가 원시 코드로 노출되고 필터 목록에도 없다.

| 분류 | 누락 코드 |
|---|---|
| 2FA (12종) | `2fa.setup` `2fa.enabled` `2fa.disabled` `2fa.disable.blocked` `2fa.admin.reset` `2fa.challenge` `2fa.verify.success` **`2fa.verify.fail`** `2fa.locked` `2fa.recover.*` `2fa.grace_start` |
| 계정 잠금 | **`login.locked`** |
| 첨부 | `attachment.add` `attachment.remove` |
| 개인정보 | `pii.request` **`pii.approve`** `pii.reject` `pii.notice` (`pii.view`는 라벨만 있고 필터 없음) |
| 설정·연동 | `settings.upload` `settings.redmine` `redmine.import` `redmine.token.set/delete` |
| 템플릿 | `template.system.create/update/delete` |

라벨 맵(`ACTS`)과 필터 목록(`KNOWN_ACTS`)이 서로 어긋나 있는 것도 문제다. 월간 감사 리포트의 `isAdminAction()`도 `2fa.admin.reset`만 예외 처리해 나머지 2FA 사건은 "관리자 작업"에 안 잡힌다.

**조치**: 백엔드 행위 코드를 단일 출처로 두고 라벨·필터를 거기서 파생시킨다.

### 🟡 D-5. 태그를 붙일 수는 있는데 태그로 찾을 방법이 없다
`중간` · QA2 발견

태그 입력·저장·표시는 되는데 **소비 경로가 0개**다. 검색은 제목+본문만 대상(`qa2tag` 검색 → 0건), 태그 칩 클릭도 무반응(`×` 삭제만 동작). 사용자가 태그를 붙이는 노력이 전부 버려진다.

### 🟡 D-6. 폴더에 넣은 노트를 최상위로 되돌릴 수 없다
`중간` · QA2 발견

이동 모달 목적지에 "루트(최상위)"가 없고, 트리 빈 영역 드롭도 미구현(`dragOverId` 주석의 `"__ROOT__"`는 구현 안 된 잔재). 모달 헤더는 현재 부모를 "루트 (최상위)"라 표시해 루트가 1급 위치임을 인정하면서도 **그리로 돌아갈 길이 없다.** 오조작을 사용자가 스스로 되돌릴 수 없다.

### 🟡 D-7. 삭제된 위키링크가 정상으로 보이고, 클릭하면 보던 노트까지 닫힌다
`중간` · QA3 발견

대상 노트를 삭제하면 삭제 경고 모달이 "그 링크들은 '연결할 수 없음'이 됩니다"라고 **명시**하는데, 실제로는 파란 정상 링크 그대로 남는다. 클릭하면 편집기가 사라지고 "열린 노트가 없습니다" 빈 화면 — **작업 중이던 노트까지 닫히고 아무 메시지도 없다.** 새로고침해야 `🔒 연결할 수 없음`으로 바뀐다.

추정 원인: `WikilinkWidget.eq()`가 id·label만 비교해 대상이 사라져도 위젯이 재생성되지 않음.

### ⚪ D-8. 업로드 허용 확장자에 잘못된 문자열이 검증 없이 저장된다
`낮음` · QA4 발견

`.BAD!` 입력 → `bad!`로 저장. 화면 안내("점 없이 소문자")와 달리 프런트·백엔드 모두 검증이 없다. 보안 완화는 아니고 **조용한 오설정** — 관리자는 허용했다고 믿지만 해당 형식 업로드는 계속 거부된다.

## 4. 교차 검증된 패턴 — 4명이 독립적으로 같은 것을 지적

서로 다른 화면을 맡은 테스터가 독립적으로 같은 문제를 짚었다면 국소적 취향이 아니라 **제품 전반의 일관성 결함**이다.

### P-1. 파괴적 동작의 확인 방식이 화면마다 다르다 — 4/4 전원 지적

| 화면 | 확인 방식 |
|---|---|
| 휴지통 영구삭제 | 인라인 2단계 (`영구 삭제 → 확인/취소`) |
| 노트 삭제 | LinkWarnDialog (앱 모달) |
| 이동 | MoveWarnDialog (앱 모달) |
| 가입 반려·역할/팀 삭제·사용자 비활성화 | 앱 모달 |
| **공유 링크 취소 (index)** | **확인 없음 — 즉시 실행** |
| **공유 링크 취소 (admin)** | **네이티브 `confirm()`** |
| **개인 템플릿 삭제** | **네이티브 `confirm()`** |
| **시스템 템플릿 삭제** | **네이티브 `confirm()`** |
| **첨부 삭제** | **네이티브 `confirm()`** |

네이티브 대화상자는 모노톤 디자인·다크 모드와 이질적이고 `qa1.localhost:8341 says` 같은 출처 문구가 그대로 노출된다. 특히 **공유 모달의 "복사"와 "취소"는 나란히 붙은 같은 크기 버튼**인데 취소는 확인 없이 즉시 실행되고 되돌릴 수 없다.

### P-2. 토스트가 1.5초 만에 사라진다 — 3/4 지적

`TOAST_MS = 1500`이 성공·실패를 구분하지 않는다. 그런데 아래는 전부 토스트가 **유일한 통지 채널**이다.

- `서버 동기화 실패: Failed to fetch` (D-2의 유일한 신호)
- `프로필에서 Redmine 키를 먼저 등록하세요`
- `만료 일수는 1~365 사이여야 합니다: 0`
- `허용하지 않는 파일 형식입니다: .exe`

한국어 한 문장을 읽기에 1.5초는 짧고 다시 볼 방법이 없다. QA 중 실제로 "아무 반응이 없다"고 오인한 사례가 나왔다. **실패 토스트 4~5초 + 닫기 버튼**이 최소 조치다.

### P-3. 되돌릴 수 없는 동작에 되돌리기 수단이 없다 — 3/4 지적

공유 링크 취소(재발급 불가), 노트 삭제(휴지통을 알아야 함), 첨부 삭제, 루트로 되돌리기 불가(D-6). 삭제 토스트에 "실행 취소"를 붙이는 것만으로 상당 부분 해소된다.

## 7. 검증 방법과 한계

### 방법
- 서버 4대를 **포트·DB·업로드 디렉토리까지 완전 분리**해 기동 (8341~8344). 한 대로 돌리면 전역 설정(업로드 정책·보안 정책)·감사 집계·계정 공유가 서로를 밟아 가짜 FAIL/PASS가 섞인다
- 각 테스터가 ego-lite의 **격리 task space**에서 실화면을 보며 조작. DOM 확인만으로 PASS 판정하지 않고 레이아웃 관련 항목은 스크린샷으로 육안 확인
- 테스터는 코드 수정·git 조작 금지 (QA와 수정 분리)

### 한계
| 항목 | 사유 |
|---|---|
| PDF 내보내기 *실행* | `window.print()` 네이티브 대화상자가 자동화 세션을 블록 (메뉴 렌더·코드 경로만 확인) |
| 2FA 복구 코드 실제 수신·검증 | 이 환경에 SMTP 미설정 (`NoopMailSender`) — UI 전환만 확인 |
| 관리자 반응형 S7·S8 스크린샷 | `Page.captureScreenshot` 타임아웃 — DOM 실측값(요소 폭·overflow·클리핑 검사)으로 대체 검증 |
| 네이티브 `confirm()` 경로 | 대화상자가 실제로 뜨는 것을 확인한 뒤, 진행을 위해 `window.confirm`을 스텁 처리하고 동작 검증 |

### 환경 이슈 (앱 결함 아님)
4개 서버를 같은 브라우저 프로필에서 쓰는데 **쿠키는 포트를 구분하지 않는다.** `JSESSIONID`가 호스트 `localhost` 하나로 공유되어 다른 테스터가 로그인하면 세션이 덮여 강제 로그아웃되는 일이 초반에 발생했다. 각 테스터가 `qa1.localhost` / `qa2.localhost` / `[::1]` 등으로 오리진을 분리해 해결했다. **폐쇄망 실배포는 서버가 하나이므로 제품 영향 없음** — 다만 향후 병렬 QA 시 서버별 호스트명 분리를 처음부터 설계에 넣어야 한다.
