# 노트 템플릿(시스템·개인 양식) 설계

> 작성일 2026-08-18 · 상태: 설계 확정 · 다음 단계: 구현 계획(writing-plans)

## 배경과 목표

같은 형식의 글(회의록·주간보고·장애보고)을 반복해서 쓰는데, 매번 이전 노트를 찾아 열고 형식을 눈으로 베껴야 한다. 위키링크 스펙(`2026-06-18-위키링크-지식그래프-design.md`)에서 "문서 템플릿"을 후속 증분으로 미뤄둔 항목이 이것이다.

목표는 하나다. **미리 만들어둔 양식을 새 노트에 그대로 가져다 붙이는 것.** Redmine 이슈 임포트와 같은 조작감 — 모달을 열고, 목록에서 고르고, 미리보기를 확인하고, `삽입`을 누르면 커서 위치에 마크다운이 들어간다.

현재 코드베이스에 있는 유일한 유사물은 `frontend/src/components/Editor.tsx:48`의 `TEMPLATES` 상수(표·코드·mermaid·시퀀스·이미지 5종)다. 이것은 툴바 버튼이 삽입하는 **블록 스니펫**이며 사용자가 만들거나 저장할 수 없다. 본 스펙의 노트 템플릿과는 별개 기능이고, 그대로 둔다.

### 범위 (v1)

**포함:** 템플릿 테이블 1개, 사용자 CRUD API, 관리자 시스템 템플릿 CRUD API, 에디터 툴바 → 템플릿 모달(목록·미리보기·삽입·현재 노트로 저장), 관리자 화면 1개.

**제외(아래 §8):** 변수 치환, 팀 공유 템플릿, 덮어쓰기, 수동 정렬, 제목 자동 채움.

## 핵심 설계 결정

### D1. 노트가 아니라 별도 테이블

템플릿을 "특정 폴더 아래의 노트"로 표현하는 방법도 있었으나 채택하지 않았다.

- 시스템 템플릿용 공용 폴더는 곧 **ACL 설계**(모두 read / 관리자만 write)를 요구한다. deny-sticky·상속 해석·public exclude가 전부 개입한다.
- 폴더가 이동·삭제·이름변경되면 기능이 깨진다. 트리 원칙상 이름은 라벨일 뿐이므로 "이름이 템플릿인 폴더"에 의미를 부여하는 것은 설계 위반이다.
- 사용자 트리에 기능용 폴더가 섞여 시야를 오염시킨다.

별도 테이블은 **권한 엔진과 완전히 분리**된다. 템플릿은 리소스 트리 밖의 객체이고, 권한 판정은 "소유자가 나인가" 한 줄이다. 이것이 이 기능을 얇게 유지하는 핵심이다.

### D2. `owner_id` 하나로 시스템/개인을 구분

역할·플래그 컬럼을 따로 두지 않는다.

| `owner_id` | 의미 | 쓰기 주체 |
|---|---|---|
| `NULL` | 시스템 템플릿 | 관리자만 (`/api/admin/templates`) |
| 사용자 id | 개인 템플릿 | 본인만 (`/api/templates`) |

목록 조회는 `WHERE owner_id IS NULL OR owner_id = :me` 한 번으로 두 종류를 모두 얻는다.

### D3. `owner_id`에 FK를 걸지 않는다

`user_redmine_token`은 `REFERENCES app_user(id) ON DELETE CASCADE`를 쓰지만, 템플릿은 다르다. local 모드(`worknote.mode=local`)는 무인증 단일 사용자라 `app_user` 행이 없고 `AuthFilter`도 등록되지 않는다. 이 모드에서도 개인 템플릿을 쓸 수 있어야 하므로 소유자 키를 상수 `'local'`로 저장한다. FK가 있으면 이 행이 들어가지 못한다.

```java
/** 현재 요청의 템플릿 소유자 키. local 모드(AuthFilter 미등록)는 단일 사용자라 상수. */
private static String ownerKey(HttpServletRequest req) {
    UserRow u = (UserRow) req.getAttribute(AuthFilter.CURRENT_USER);
    return u != null ? u.id() : "local";
}
```

FK 부재의 대가는 사용자 삭제 시 개인 템플릿이 고아로 남는 것이다. 첨부 파일과 달리 디스크를 차지하지 않는 텍스트 몇 KB이고, 관리자 화면에서 사용자 삭제는 드문 사건이므로 정리 스케줄러는 두지 않는다(첨부 회수기의 교훈: 근거 없는 자동 삭제기는 위험만 늘린다).

### D4. 삽입은 기존 경로 재사용

`App.tsx:542`가 `RedmineImportPanel`에 넘기는 `onInsert` 콜백이 이미 정확히 필요한 동작이다.

```ts
onInsert: (md: string): boolean => {
  const v = editorViewRef.current;
  if (!v) return false;
  cm.insertAtCursor(v, md);
  return true;
}
```

템플릿 모달도 같은 시그니처를 쓴다. 빈 노트에 삽입하면 결과적으로 전체 덮어쓰기와 같으므로 별도 덮어쓰기 버튼은 두지 않는다(§8).

### D5. 관리자 시스템 템플릿은 관리자 앱에서

템플릿 모달 안에서 관리자에게만 추가 버튼을 노출하는 방법도 검토했으나, 관리 동선을 관리자 앱으로 모으는 기존 구조(`Uploads`·`Redmine` 화면)와 일관되게 간다. 사용자 모달은 시스템 템플릿에 대해 **읽기 전용**이므로 조건부 UI 분기가 사라지고, 관리자 화면은 `Uploads.tsx` 패턴을 그대로 복제한다.

## 데이터 모델

`backend/src/main/resources/db/migration/sqlite/V13__note_template.sql`

```sql
-- V13__note_template.sql  (ANSI 지향 — Oracle 전환 시 TEXT→VARCHAR2/CLOB)
CREATE TABLE note_template (
  id         TEXT PRIMARY KEY,
  owner_id   TEXT,              -- NULL = 시스템 템플릿, 그 외 = 소유자 user id(local 모드는 'local')
  name       TEXT NOT NULL,
  body       TEXT NOT NULL,     -- 마크다운 원문
  created_at TEXT NOT NULL,     -- ISO_LOCAL_DATE_TIME
  updated_at TEXT NOT NULL
);
CREATE INDEX idx_note_template_owner ON note_template(owner_id);

INSERT INTO note_template (id, owner_id, name, body, created_at, updated_at) VALUES
  ('tpl-meeting', NULL, '회의록', '## 개요
- 일시:
- 장소:
- 참석자:

## 안건
1.

## 결정 사항
-

## 액션 아이템
| 담당 | 할 일 | 기한 |
| --- | --- | --- |
|  |  |  |
', '2026-08-18T00:00:00', '2026-08-18T00:00:00');
```

`주간보고`·`장애보고`도 같은 형태의 `INSERT` 문으로 이어 쓴다. 시드 3종은 헤딩과 표 골격만 담은 최소 양식이다.

**본문은 마크다운 원문 그대로, 개행을 리터럴로 적는다.** `char(10)` 연결로 한 줄에 욱여넣는 방법도 있으나 채택하지 않았다 — 마이그레이션 파일에서 양식이 눈에 보이지 않으면 리뷰할 때 무엇이 사용자 화면에 뜨는지 알 수 없고, 나중에 문구를 고칠 때마다 연결 연산자를 세어야 한다. 읽기 어려운 시드는 방치되고, 방치된 시드는 곧 아무도 쓰지 않는 기본 양식이 된다.

Flyway의 SQL 파서는 따옴표 문자열을 추적하므로 리터럴 내부의 개행은 구문 종결자로 오인되지 않는다. 이 전제는 **구현 1단계의 `SchemaMigrationTest`가 실제 마이그레이션을 돌려 검증**한다. 만약 파서가 깨지면 그때 `char(10)` 연결로 후퇴하되, 그 경우에도 시드 본문은 별도 리소스 파일로 빼내 가독성을 지킨다.

관리자가 화면에서 수정·삭제할 수 있으므로 마이그레이션은 초기값 제공에 그친다.

정렬 컬럼은 두지 않는다. 목록은 **시스템 그룹 → 개인 그룹**, 각 그룹 내 `name` 오름차순으로 고정한다.

### 입력 상한

`backend/src/main/java/com/worknote/template/TemplateLimits.java` — `NodeLimits` 패턴을 따른다.

```java
public static final int NAME_MAX = 50;
public static final int BODY_MAX = 100_000;   // 양식은 노트 본문(1_000_000)보다 짧다
public static final int PER_OWNER_MAX = 50;   // 개인 템플릿 개수 상한
```

`PER_OWNER_MAX` 초과 시 422 + 한국어 메시지(`템플릿은 최대 50개까지 만들 수 있습니다`). 이 기능의 오류 응답은 안정적 오류 코드가 아니라 한국어 메시지로 통일한다 — 별도 코드 상수를 두지 않는다. 시스템 템플릿에는 개수 상한을 적용하지 않는다(관리자만 만들 수 있고 감사에 남는다).

## 백엔드

새 패키지 `com.worknote.template` — `redmine` 패키지와 같은 층위.

| 파일 | 역할 |
|---|---|
| `NoteTemplateRow.java` | 행 레코드 |
| `NoteTemplateMapper.java` + `mappers/NoteTemplateMapper.xml` | listVisible(owner) / listSystem / find(id) / insert / update / delete / countByOwner |
| `NoteTemplateService.java` | 소유권 검사·상한 검증·id 생성(UUID)·시각 스탬프. **검증 단일 출처** — 이름/본문 공백·길이 검사는 전부 여기서 하고 `VaultException.invalid`(422)로 통일한다 |
| `TemplateController.java` | `/api/templates` — 사용자용. `TemplateRequest`/`TemplateResponse`는 이 클래스 내부 public record다(별도 `dto/` 패키지 없음) |
| `AdminTemplateController.java` | `/api/admin/templates` — 관리자용. `TemplateController`의 record를 재사용한다 |

`TemplateRequest`/`TemplateResponse`에는 **Bean Validation(`@NotBlank`/`@Size`)을 의도적으로 달지 않는다.** 검증을 DTO와 서비스에 나눠 두면 같은 성격의 실패(빈 이름 등)가 DTO 위반은 400(`MethodArgumentNotValidException`)으로, 서비스 위반은 422(`VaultException.invalid`)로 갈려 클라이언트가 두 상태 코드를 다 처리해야 한다. 검증을 `NoteTemplateService`에만 두고 전부 422로 통일한 이유다.

### 엔드포인트

| 메서드 | 경로 | 동작 | 실패 |
|---|---|---|---|
| GET | `/api/templates` | `owner_id IS NULL OR owner_id = 나`. 응답에 `system: boolean` 포함 | — |
| POST | `/api/templates` | `owner_id = 나` 강제 | 422 상한 초과 |
| PUT | `/api/templates/{id}` | 내 것만 | 403 시스템·타인 것, 404 없음 |
| DELETE | `/api/templates/{id}` | 내 것만 | 403 / 404 |
| GET | `/api/admin/templates` | 시스템 템플릿만 | 403 비관리자 |
| POST | `/api/admin/templates` | `owner_id = NULL` 강제 | 403 |
| PUT | `/api/admin/templates/{id}` | 시스템 것만 | 403, 404 |
| DELETE | `/api/admin/templates/{id}` | 시스템 것만 | 403, 404 |

- 관리자 경로는 전부 `AdminGuard.requireAdmin(user(req))`로 시작한다. 이 가드는 local 모드(user=null·단일 사용자=관리자)를 통과시키므로 local 모드에서도 시스템 템플릿을 관리할 수 있다.
- 관리자 변경은 `audit.log(u, "template.system.create|update|delete", name, ip)`로 남긴다. 사용자 개인 템플릿 CRUD는 감사 대상이 아니다(개인 작업 노이즈).
- 소유권 위반은 404가 아니라 403으로 답한다. 템플릿 id는 열거 가치가 없는 UUID이고, 403이 원인을 정확히 알려 준다.

### 권한 모델과의 관계

**노트 ACL은 개입하지 않는다.** 템플릿은 노트·폴더가 아니므로 `PermissionService`·`VaultGuard`를 호출하지 않는다. 판정은 `owner_id` 일치 여부와 `AdminGuard`뿐이다. 시스템 템플릿은 로그인한 모든 사용자에게 read다 — 회사 표준 양식이므로 의도된 동작이다. 따라서 **시스템 템플릿에 기밀을 담지 않는다**는 운영 원칙을 관리자 화면에 안내 문구로 표기한다.

### 템플릿 모달

`RedmineImportPanel`의 분할 레이아웃을 축소해 재사용한다(`rm-` 클래스 대신 `tpl-` 접두).

```
┌──────────────┬─────────────────────────┐
│ 시스템        │  # 회의록                │
│  · 회의록  ▸  │  ## 참석자               │
│  · 주간보고   │  ## 안건                 │
│  · 장애보고   │  ## 결정사항             │
│ 내 템플릿     │                         │
│  · 배포체크 ✎✗│                         │
│              │            [삽입]        │
├──────────────┴─────────────────────────┤
│ [+ 현재 노트로 새 템플릿]                │
└────────────────────────────────────────┘
```

- 좌측: 2그룹 목록. 개인 항목에만 ✎(이름·본문 수정) ✗(삭제) 노출.
- 우측: `renderMarkdown` 재사용 미리보기. mermaid는 템플릿 골격에 사실상 쓰이지 않으므로 `enhanceMermaid`는 호출하지 않는다.
- `[삽입]` → `onInsert(body)` → 토스트 → 모달 닫기 (Redmine의 `doInsert`와 동일 흐름).
- `[+ 현재 노트로 새 템플릿]` → 이름 입력 프롬프트(모달 내 인라인 입력) → 현재 노트 `content`로 POST. 열린 노트가 없으면 버튼 비활성.
- Escape로 닫기(`useEscClose`), 오버레이 클릭으로 닫기 — 기존 모달 관례.

### 진입점

- **에디터 툴바**: `App.tsx`의 `etoolbar`, Redmine 버튼 옆에 `clipboard` 아이콘 버튼. 노출 조건은 `storageMode === "http"`. localStorage 모드는 백엔드가 없어 템플릿을 저장할 곳이 없으므로 버튼을 숨긴다(Redmine과 동일 정책).
- **관리자 앱**: `AdminApp.tsx`의 `NAV`에 `{ id: "templates", label: "템플릿", icon: "clipboard" }` 추가 + `screenMap` 등록 + 헤더 설명 문구.

관리자 편집 폼에는 본문 입력 옆에 `renderMarkdown` 미리보기를 나란히 둔다. 시스템 템플릿은 전 사용자가 보는 화면이므로, 저장 후 사용자 모달을 열어봐야 결과를 아는 구조면 양식이 깨진 채 배포된다. 미리보기 컴포넌트는 템플릿 모달과 동일한 코드를 쓴다.

### 순수 함수로 뽑는 결정 로직

프런트 테스트 관례(React 렌더/e2e 없음)에 따라 판정 로직을 컴포넌트 밖으로 뺀다.

```ts
// templateList.ts
export interface TemplateItem { id: string; name: string; body: string; system: boolean }
export function groupTemplates(items: TemplateItem[]): { system: TemplateItem[]; mine: TemplateItem[] }
export function canEdit(item: TemplateItem): boolean          // = !item.system

// templateValidation.ts
export function validateName(name: string): string | null     // 공백·길이 → 오류 메시지
export function validateBody(body: string): string | null     // 빈 본문·상한
```

테스트 DB는 **네임드 인메모리**로 격리한다(익명 `::memory:?cache=shared`는 JVM 전역 공유라 PK 충돌 — 기존 함정). 쓰기를 하는 신규 템플릿 테스트 클래스(`NoteTemplateApiTest`, `AdminTemplateApiTest`, `NoteTemplateMapperTest`)는 이 규칙대로 네임드 인메모리(`tplmem`)를 쓴다.

**예외 — `SchemaMigrationTest`:** V13 스키마·시드 검증(`v13_createsNoteTemplateTableAndSeeds`)은 새 클래스로 분리하지 않고 기존 `SchemaMigrationTest`에 추가했다. 이 클래스는 저장소 관례상 모든 마이그레이션 검증이 한곳에 모이는 자리이고, 익명 공유 DB(`::memory:?cache=shared`)를 쓴다. 네임드 격리 규칙이 막으려는 것은 **여러 테스트가 같은 공유 DB에 같은 PK로 쓰기 경쟁**을 벌이는 상황인데, `SchemaMigrationTest`의 테스트는 전부 `SELECT`뿐인 읽기 전용이라 이 충돌이 애초에 발생하지 않는다. 따라서 이 클래스에 한해 익명 공유 DB를 그대로 쓴다(참고: `backend/build.gradle`에 `maxParallelForks` 설정이 없어 테스트는 순차 실행되므로 클래스 간 레이스도 없다).

## 제외 항목과 근거

| 제외 | 근거 |
|---|---|
| `{{date}}`·`{{작성자}}` 변수 치환 | 치환 엔진·문법·이스케이프·미리보기 반영까지 스코프가 배로 늘어난다. 삽입 후 손으로 고치는 비용이 낮다. 필요해지면 `body` 렌더 시점 후속 증분 |
| 팀 공유 템플릿 | `owner_id`가 팀을 가리키게 되는 순간 팀 멤버십·deny 해석이 다시 붙는다. 시스템/개인 2단계로 시작하고 실사용 요구가 나오면 증분 |
| 전체 덮어쓰기 버튼 | 새 노트는 비어 있어 커서 삽입 = 덮어쓰기. 작성 중인 글을 날릴 위험만 추가된다 |
| 드래그 순서 정렬 | `sort` 컬럼·재정렬 API·DnD 핸들러가 필요하다. 이름순으로 충분 |
| 노트 제목 자동 채움 | 삽입은 본문만 건드린다는 규칙이 단순하다. 제목까지 바꾸면 "왜 제목이 바뀌었나" 되돌리기 요구가 생긴다 |
| localStorage 모드 지원 | 저장소가 없다. http 모드에서만 버튼 노출 |
